# 选案后携带案件材料进模型设计

**日期：** 2026-09-05  
**状态：** 已定稿  
**范围：** 对话已选 `case_id` 时，编排与单智能体访问模型携带委托合同与证据材料上下文；证据上传生成短说明；证据全文按需工具拉取。

---

## 1. 背景与目标

### 现状

- 对话可选案件；`case_id` 主要用于 RBAC（`cap.chat` / `cap.judge` / `cap.doc_write`）。
- 案件元数据含 `contract_file_ids`（最多 1）与 `evidence_file_ids`（最多 10）；文件经 `FileService` 解析存 `text_content`。
- 编排与单智能体**不会**把上述案件材料自动注入模型上下文。

### 目标

1. 用户在对话中选择案件后，**编排（`/api/orchestrate`）与单智能体对话**访问模型时均携带案件材料信息。
2. **委托合同：** 尽量注入解析后的**全文**（超长截断）。
3. **证据材料：** 默认注入**文件名 + 类型 + ≤200 字说明**；正文由 Agent **按需工具**再取。
4. 证据在**上传时**解析，并生成不超过 200 字的说明，供模型理解大意。

### 非目标

- 不改管理端上传交互流程（可在服务端保存后异步/同步补说明）。
- 不做证据向量检索或写入知识库。
- 不改变未选案件时的行为。

---

## 2. 决策摘要

| 议题 | 决定 |
|------|------|
| 覆盖路径 | 编排 + 单智能体（方案 B） |
| 架构 | 服务端统一 `build_case_material_context(case_id)`（方案 1） |
| 委托合同 | 全文注入（可截断） |
| 证据默认 | 文件名 + 类型 + ≤200 字说明 |
| 证据全文 | 工具按需拉取（`get_case_evidence_file`） |
| 说明生成时机 | 证据上传时；存量无说明则组装或取文前补生成并回写 |

---

## 3. 行为细节

### 3.1 证据说明（上传）

- 证据文件保存并 `_extract_text` 后，调用 LLM（或启发式回退）生成中文说明，**不超过 200 字**。
- 写入文件记录的 `description`（若需与用户手填描述区分，可用 `metadata.evidence_brief`，并以该字段优先注入；实现时二选一并在计划中固定）。
- LLM 失败：用正文前若干字压缩为 ≤200 字，或标记「暂无摘要」；**不阻断上传**。

### 3.2 上下文组装

`build_case_material_context(case_id, user_id, …) -> str | None`：

- 无 `case_id` 或无案件 → 返回空。
- 校验用户对该案有 `cap.chat`（或与对话同等权限）；否则不注入（调用方已 403 的可不重复）。
- 输出结构建议：

```text
【当前案件】
案号/标题/类型：…

【委托合同】
文件名：…
（全文或截断正文）

【证据材料】
1. file_id=… | 文件名=… | 类型=… | 说明=…
2. …
（如需某份证据全文，请调用工具 get_case_evidence_file）
```

- 合同无文件：写明「未上传委托合同」。
- 证据列表为空：写明「未上传证据材料」。
- 合同全文截断上限：实现计划规定（建议约 20_000 字符，截断处标注「…[已截断]」）。
- 存量证据无说明：组装时补生成并回写，再注入。

### 3.3 注入点

| 路径 | 行为 |
|------|------|
| `/api/orchestrate` | 有 `case_id` 时，将材料块并入发给分析/文书等子流程的用户侧上下文（与 `user_text` 并列或前置），不要求客户端改字段。 |
| 单智能体对话 API | 同样在拼模型输入前注入；与本轮用户上传 `file_ids` 并存（案件材料 ≠ 本轮附件）。 |

客户端仍只传 `case_id`（及现有消息）；材料由服务端按案加载。

### 3.4 按需工具

- 名称：`get_case_evidence_file`（或等价 MCP/编排内部 tool）。
- 入参：`file_id`（必填）；隐式使用当前请求的 `case_id`。
- 校验：`file_id` ∈ 该案 `evidence_file_ids`；调用方有权访问该案。
- 返回：解析正文（可截断，建议约 15_000 字符）+ 文件名/类型。
- 非该案证据或无权 → 明确错误，不泄露他案内容。
- **本期工具仅覆盖证据**；合同已在默认上下文中。

### 3.5 失败与降级

| 情况 | 行为 |
|------|------|
| 文件缺失 / 正文为空 | 清单仍列文件名；说明「无法解析正文」 |
| 说明生成失败 | 「暂无摘要」 |
| 工具失败 | 返回可读错误，对话继续 |

---

## 4. 主要改动面（实现指引）

| 区域 | 责任 |
|------|------|
| 新模块（如 `server/case_materials.py`） | 组装上下文、补生成说明、截断 |
| `FileService` / 案件材料挂接上传路径 | 证据上传后触发生成说明 |
| `run_orchestrate` / `http_api_extra.handle_orchestrate` | 注入 + 注册按需工具 |
| 单智能体对话处理（`mcp_server` 对话路径） | 同样注入 |
| 测试 | 组装格式、权限、工具越权拒绝、说明长度 |

---

## 5. 验收

1. 选案且有合同+证据：编排与单智能体请求的模型输入含合同全文块与证据清单（含 ≤200 字说明）。
2. 未选案：无案件材料块。
3. 证据新上传后，说明字段有内容且 ≤200 字（或失败占位）。
4. 调用 `get_case_evidence_file` 可取该案证据正文；他案 `file_id` 被拒绝。
5. 无 `cap.chat` 不能通过工具读材料。
