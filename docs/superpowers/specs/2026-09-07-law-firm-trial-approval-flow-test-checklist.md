# 办案阶段 + 文书审批流 · 逐点测试清单（P0）

**日期：** 2026-09-07  
**对应设计：** `2026-09-07-law-firm-trial-approval-flow-design.md`  
**前提：** 已启动 MCP（常见 `8000`/`8001`）与静态页 `http://localhost:8888`；浏览器建议无痕或分账号登录时「退出再登」。

**建议账号（建完后填在表里）：**

| 角色 | 账号 | 密码 | 用途 |
|------|------|------|------|
| 所长 | `director` | `ChangeMe123!` | 建用户、建案、可代审 |
| 合伙人 | ________ | ________ | 终审、可推进阶段 |
| 主办 | ________ | ________ | 一审、推进阶段 |
| 助理 | ________ | ________ | 对话起草、提交审核 |

> 案级角色在「新建案件」里指定；用户管理里可无「所级角色」（显示「办案人员」即可）。三人必须是不同用户。

---

## A. 环境与账号

- [ ] **A1** 打开 `http://localhost:8888/admin.html`，用 `director` 登录成功。
- [ ] **A2** 进入 **用户管理**（`admin_users.html`）→ **新建用户**，建齐合伙人 / 主办 / 助理三人（账号状态=启用）。
- [ ] **A3** 退出 director，分别用三人登录首页一次，确认能进系统（再退出）。

---

## B. 建案与阶段推进

- [ ] **B1** `director`（或有建案权限者）打开 **案件管理**（`admin_cases.html`）→ **新建案件**。
- [ ] **B2** 填写案号/标题；**合伙人**、**主办律师**必选且不同人；**助理**选测试助理 → 保存成功。
- [ ] **B3** 列表中该案阶段为 **收案**（`intake`）或等价文案。
- [ ] **B4** 用 **主办** 或 **合伙人** 或 `director` 登录 → 同一案件行点 **「推进至材料完备」** → 确认 → 阶段变为材料完备。
- [ ] **B5** 再点 **「推进至策略与文书」** → 确认 → 阶段变为策略与文书（`strategy_docs`）。
- [ ] **B6（负例）** 用 **助理** 登录 → 案件行 **不应** 出现可用的阶段推进按钮，或点推进返回无权限（403）。
- [ ] **B7（负例）** 尝试跳级（若 UI 只给下一档则跳过）：不可从 `intake` 直接到 `strategy_docs`。

---

## C. 助理起草并提交审核（核心）

- [ ] **C1** 用 **助理** 登录。
- [ ] **C2** 打开对话页：`http://localhost:8888/mcp_client.html`（或首页选案进入对话）。
- [ ] **C3** **绑定本案**：顶栏案件选择器选刚建的案，或 URL 加 `?case_id=<案件ID>`。确认当前案件不是「未选 / 全所」。
- [ ] **C4** 发送例如：  
  `请根据本案写一份民间借贷民事起诉状（要素式）`  
  等待生成完成，出现 **文书卡片**（含预览/下载、审批状态徽章，初始多为「草稿」）。
- [ ] **C5** 卡片上有 **「提交审核」**；下载按钮文案为 **「下载工作稿」**（或同类非定稿文案），**不是**「定稿下载」。
- [ ] **C6** 点击 **「提交审核」** → 提示成功；徽章变为待主办审（如「待主办」/ `pending_lead`）；提交按钮应变灰或消失。
- [ ] **C7（负例）** 清除案件绑定（未选案）后再生成一份文书：卡片提示 **「未绑定案件，无法进入所内审批」**，**无**「提交审核」。

---

## D. 主办一审

- [ ] **D1** 退出助理，用 **主办** 登录。
- [ ] **D2** 打开 **审批待办**（`admin_approvals.html`，或管理首页「审批待办」卡片）。
- [ ] **D3** 列表可见刚提交的文书：含案件号、标题、步骤（主办）、提交时间。
- [ ] **D4（负例·驳回）** 可选：点 **驳回**，不填意见应无法提交；填意见后驳回 → 待办消失；助理侧文书回到草稿，可再提交。若测驳回，测完后助理再提交一次再继续 D5。
- [ ] **D5** 点 **通过** → 确认 → 该条待办消失。
- [ ] **D6（负例）** 用 **助理** 打开审批待办：不应能通过主办/合伙人任务（列表空或操作 403）。

---

## E. 合伙人终审与定稿

- [ ] **E1** 用 **合伙人** 登录 → **审批待办**，可见步骤为合伙人的任务。
- [ ] **E2** 点 **通过** → 文书变为 **已定稿**（`approved`）。
- [ ] **E3** 用助理（或任意有权成员）回对话页，找到该文书卡片：徽章 **已定稿**，主下载按钮为 **「定稿下载」**。
- [ ] **E4** 点击 **定稿下载**，文件可正常下载打开。
- [ ] **E5（可选）** `director` 登录审批待办：对合伙人节点任务应可代审通过（若你们启用了 director 代审）。

---

## F. 文件鉴权（安全冒烟）

- [ ] **F1** 未登录（无痕窗口）直接访问下载 URL（从网络面板复制 `/api/files/.../download`）→ **401**。
- [ ] **F2** 用 **非本案成员** 账号登录后访问同一 URL → **403**。
- [ ] **F3** 本案助理/主办/合伙人或 `director` 访问 → **200** 且能下文件。

---

## G. 捷径与边界（可选）

- [ ] **G1** 用 **主办** 本人绑案生成文书并 **提交审核**：应 **跳过主办步**，直接进合伙人待办。
- [ ] **G2** 管理首页 `admin.html`：有审批权限时，「审批待办」卡片显示待办数量（有任务时 > 0）。
- [ ] **G3** 阶段停在 `intake` / `materials_ready` 时仍可对话生成 draft（一期不强制拦起草）；提交审核行为以当前实现为准，记录是否允许。

---

## 最短快乐路径（只勾这些也能验收主链路）

1. [ ] B1–B5 建案并推进到 **策略与文书**
2. [ ] C1–C6 助理绑案生成起诉状并 **提交审核**
3. [ ] D1–D3、D5 主办 **通过**
4. [ ] E1–E4 合伙人 **通过** → **定稿下载**
5. [ ] F1 未登录不可下载
